# Experience & visual direction — v0.1 (exploratory)

**Desired mood:** calm, rich, premium, warm, human, beautiful; never loud, preachy, childish, or overloaded.

## Design principles
1. **Quiet hierarchy:** Today, one chosen next step, and meaningful history. No endless category walls.
2. **Progressive disclosure:** Complex challenge controls appear only when requested.
3. **Meaningful motion:** Animations respond to user actions and represent transitions, not distractions.
4. **Accessible by design:** Text contrast, readable sizing, large targets, clear non-color cues, and reduced-motion/static alternatives.
5. **Creative consistency:** Each screen follows one art direction, icon language, typography scale, spacing, and motion rules.
6. **Reality before metaphor:** Beautiful visual growth must never exaggerate actual challenge completion.
7. **Offline-first exploration:** Prefer resilience and user control; decide architecture after feasibility review.

## Art and motion exploration
- Candidate visual language: original miniature landscapes, hand-crafted sculptural objects, subtle flora, soft directional light, restrained texture.
- Candidate states: dawn, daylight, evening, night; a living personal landscape can change with time and intentional practice.
- Blender is a candidate for original modeling/rendering and exported animation assets; assess Android performance and asset pipeline first.
- Avoid purchased/borrowed visual assets without licenses.
- Reduce motion for accessibility and offer static artwork.
- No final palette, logo, mascot, typography, screen layout, or component set approved.

## Must-prototype journeys before engineering
- First launch/onboarding and selecting personal domains.
- Creating one 21-day challenge (single repeated activity).
- Today view and completion/partial/skip logging.
- Missed-days recovery without shame.
- Day-21 reflection and continuation beyond challenge.
- Journaling/privacy settings and data export/delete paths.

## Quality gates
- Side-by-side real Android screenshots and interaction prototype before visual approval.
- Check small screens, touch targets, animations, low-power devices, dark/light conditions, screen readers.
- Assets must be tested on device; Blender output alone is not adequate.
- Do not implement unapproved visual decisions as permanent production assets.
